# 两轮差速小车底盘固件 —— 从零到跑起来

> 目标：把"我有板子但不知道从哪下手"，变成"照着做，两小时内车能跟着指令动"。
>
> 板子：STM32F103C8T6 最小系统板（蓝丸）
> 驱动：TB6612FNG（或 DRV8833）
> 电机：带霍尔 AB 相编码器的直流减速电机 ×2

---

## 0. 这个工程里有什么

```
firmware/
├── Inc/                     头文件
│   ├── stm32f10x.h          寄存器定义（自包含，不用 ST 标准库）
│   ├── board.h              ★ 所有硬件参数集中在这里，改这里就够
│   ├── gpio_ll.h            GPIO 寄存器配置封装
│   ├── encoder.h/.c         TIM2/TIM3 硬件编码器模式
│   ├── motor.h/.c           TB6612 + TIM4 PWM
│   ├── pid.h/.c             增量式 PID
│   ├── chassis.h/.c         测速 + 斜坡 + 双轮独立 PID
│   ├── usart.h/.c           USART1 中断收发 + 环形缓冲
│   └── protocol.h/.c        ASCII 指令协议 + 遥测上报
├── Src/
│   ├── main.c               1 kHz 控制节拍 + 主循环
│   ├── system_stm32f10x.c   72 MHz 时钟树
│   └── ...
├── Startup/
│   └── startup_stm32f10x_md.s   启动文件
├── STM32F103C8Tx_FLASH.ld       链接脚本
├── tests/host/                  主机侧单元测试（PC 上直接跑，无需板子）
└── platformio.ini               PlatformIO 一键编译配置
```

**设计上的三个关键取舍**（这也是原文里踩过的坑，全部落实到了代码里）：

1. **控制节拍（1 kHz）和串口收发彻底解耦**。SysTick 里只做 PID 和计数，字符串操作全部丢到主循环。这样串口再忙也拉不长 1 ms 周期，不会出现"小车一顿一顿"。
2. **中断优先级：SysTick=1，USART1=2**。控制节拍永远抢占串口。写反了就会出现原文描述的抖动。
3. **执行器保持线性，死区交给积分项顶**。不搞"占空比抬到 180"这种补偿 —— 那样会让输出不连续，实测会形成极限环，小目标速度根本收不住。

## 1. 半小时配好开发环境（三选一）

### 方案 A：PlatformIO（最省事，推荐）

1. 下载 [VS Code](https://code.visualstudio.com/)
2. 装扩展 **PlatformIO IDE**
3. 用 VS Code 打开 `firmware` 目录
4. 左下角点 **✓** 编译，点 **→** 下载

`platformio.ini` 已经写好了，识别到蓝丸会自动配好一切。

### 方案 B：arm-none-eabi-gcc + Make

```bash
sudo apt install gcc-arm-none-eabi    # Linux
brew install arm-none-eabi-gcc        # macOS
```

然后：

```bash
cd firmware
make          # 生成 build/firmware.elf / .hex / .bin
make flash    # 用 st-flash 烧录
```

### 方案 C：Keil MDK

Keil 需要 `.uvprojx` 工程文件，而这是二进制/XML 格式，不同版本差异很大，没法通用生成。**建议先用方案 A，能跑起来再考虑迁 Keil**。

如果一定要用 Keil，按这个顺序建工程：
1. Project → New，选 `STM32F103C8`
2. 把 `Src/` 下所有 `.c` 加入 Source Group
3. 把 `Inc/` 加进 Include Paths
4. 把 `Startup/startup_stm32f10x_md.s` 加入工程（Keil 需要 Keil 语法的启动文件，可从 ST 官网补丁包取 `startup_stm32f10x_md.s`）
5. Options → Target 里勾 **Use MicroLIB**
6. 输出选 Create HEX File

## 2. 接线表（照着插，别自由发挥）

### 2.1 电源部分 —— 这里最关键

```
   电池 7.4V / 11.1V
        │
        ├──粗线──> TB6612 的 VM (Pin 8)
        │
        └──降压模块──> 5V ──> 蓝丸的 5V 脚
                              └──> TB6612 的 VCC (Pin 1, 逻辑电源)
```

**必须遵守的三条：**

- **电机电源 VM 和逻辑电源 VCC 分开走线**，不要用一根线串过去。电机启动瞬间电流可达几安，线阻上的压降会把逻辑电源拉塌。
- **两者共地，但要"星形"共地**：所有地线在电池负极一个点汇合，不要让电机电流从板子的地线上流过。
- **蓝丸的 5V 脚不要接 USB，同时接外部 5V**。二选一，否则会倒灌。

> 原文里"电机启动把单片机拉复位"的问题，99% 是这里没做好。现象是：一给占空比，板子就重启，串口打印重新出现启动信息。

### 2.2 编码器接线

| 信号 | 蓝丸引脚 | 说明 |
|---|---|---|
| 左编码器 A | PA0 | TIM2_CH1 |
| 左编码器 B | PA1 | TIM2_CH2 |
| 右编码器 A | PA6 | TIM3_CH1 |
| 右编码器 B | PA7 | TIM3_CH2 |
| 编码器 VCC | 3.3V 或 5V | 看电机规格 |
| 编码器 GND | GND | |

**注意两点：**

- **PA0/PA1 是 5V 容忍脚（FT）**，5V 输出的霍尔编码器可以直连。PA6/PA7 **不是** 5V 容忍的，如果编码器是 5V 供电输出，必须加电平转换或串 1kΩ 电阻分压。
- **开漏输出的编码器必须外接上拉**（4.7kΩ 到 3.3V）。代码里开了内部上拉兜底，但内部上拉只有约 40kΩ，长线时不够。

### 2.3 电机驱动接线（TB6612）

| TB6612 引脚 | 接到 | 说明 |
|---|---|---|
| VM (8) | 电池正极 | 电机电源，粗线 |
| VCC (1) | 3.3V 或 5V | 逻辑电源 |
| GND (2,3) | 电池负极 | 星形共地点 |
| STBY (19) | PB11 | 使能，高电平工作 |
| PWMA (15) | PB6 | TIM4_CH1，左轮调速 |
| AIN1 (16) | PB12 | 左轮方向 |
| AIN2 (17) | PB13 | 左轮方向 |
| AO1/AO2 (18,20) | 左电机 | 两根线，反了就在软件里取反 |
| PWMB (21) | PB7 | TIM4_CH2，右轮调速 |
| BIN1 (22) | PB14 | 右轮方向 |
| BIN2 (23) | PB15 | 右轮方向 |
| BO1/BO2 (24,25) | 右电机 | |

### 2.4 调试串口

| 信号 | 蓝丸引脚 |
|---|---|
| TX（板子发） | PA9 → USB-TTL 的 RX |
| RX（板子收） | PA10 → USB-TTL 的 TX |
| GND | GND |

**注意 TX 接 RX，交叉接。** 波特率 115200。

## 3. 上电自检 —— 分四步，每步都要通过才往下走

> 这是最重要的部分。**不要一次性接完就上电**，出问题会很难查。
> 每一步都单独验证，确认通过再进下一步。

### 第 1 步：只接串口，确认固件活着

只接 USB-TTL，不接电机、不接编码器。上电后串口应该看到：

```
=== DiffBot-BLUEPILL v1.0 ===
cmd: V <v> <w> | S stop | Z zero | P kp ki kd | R reset | ?
```

然后板载 LED（PC13）开始约 1 Hz 闪烁。

**如果没输出：**
- 检查 TX/RX 是否交叉
- 检查波特率是否 115200
- 检查 USB-TTL 的 GND 是否和板子共地

**如果输出是乱码：** 晶振不对。蓝丸上那个 8 MHz 小晶振如果虚焊，时钟会跑偏。用示波器看 PA8（MCO）有没有输出。

### 第 2 步：接编码器，用手转轮子

只接编码器，**不接电机电源**。串口终端里手动发：

```
V 0 0
```

这时应该持续收到遥测帧：

```
T,1234,0.000,0.000,0.000,0.000,0,0,0,0,0
```

现在**用手慢慢转左轮**，看第 7 个字段（tickL）是否变化：

- 正转 → 数字增加
- 反转 → 数字减少
- 数一下：转一整圈，这个数字应该变化 ±1600（或你实际的 `COUNTS_PER_OUT_REV` 值）

**如果数字不动：** 检查 A/B 相有没有接反、编码器有没有供电。
**如果只有正转不反转：** 说明 B 相没接上，只有单相在计数。

> ⚠️ 注意：这里有个坑。发 `V 0 0` 之后，如果 500 ms 内不再发指令，固件会判定链路超时并自动停车（这是安全保护，故意的）。所以调试时要么每 0.5 s 发一次，要么先不管它 —— 编码器计数不受停车影响。

### 第 3 步：测速检查

还是接着第 2 步，用手匀速转轮子，观察第 2、3 个字段（vL、vR）。

- 静止时应该是 `0.000`
- 转动时应该有非零值，正反转符号相反

**这里的数值对不对先不用管**，只要"转得越快数字越大、方向对"就行。精度问题第 4 章标定。

### 第 4 步：接电机，第一次让轮子转起来

**先把轮子架空（拿在手里或垫起来），确保轮子悬空。**

接上电机电源，然后发：

```
P 1800 20000 0
V 0.10 0
```

- 左轮应该开始缓慢转动，速度约 0.1 m/s
- 遥测帧里 vL 应该逐渐逼近 0.100
- 3 秒内应该稳定在 0.100 附近（误差 < 0.01）

**如果轮子不转：**
1. 先发 `V 0 0` 停车
2. 发 `V 0.5 0` 给个大目标，如果还是不转 → 硬件问题
3. 检查 STBY 是否拉高（PB11 应该是 3.3V）
4. 检查电池电压是否够（TB6612 的 VM 至少 6V）

**如果轮子转但方向反了：** 把电机的两根线对调，或者把 `motor.c` 里对应轮的 `AIN1/AIN2` 互换。

**如果转一下就停、串口重新打印启动信息：** 电源问题，回到 2.1 节。这是最典型的"电机启动把单片机拉复位"。

## 4. 标定 —— 让速度读数变成真值

前面能转起来之后，测出来的速度大概率是错的，因为 `COUNTS_PER_OUT_REV` 和 `WHEEL_RADIUS_M` 是估的。这一步把估的换成真的。

### 4.1 标定编码器分辨率（CPR）

1. 轮子悬空，先用记号笔在轮子和车架上各画一条对齐线
2. 发 `Z` 清零
3. 用手**正好转 10 圈**，回到对齐位置
4. 读遥测帧的 tickL 字段，记为 `N`
5. `COUNTS_PER_OUT_REV = N / 10`

把结果写回 `board.h` 的 `COUNTS_PER_OUT_REV`。

> 为什么会跟标称值不一样：霍尔编码器的"线数"是电机轴上的，经过减速箱后会有齿隙和比例误差。实测才准。

### 4.2 标定轮径

1. 在地面画一条 2 米的直线（用卷尺量）
2. 发 `V 0.2 0`，让车直线走完这 2 米
3. 读走完时的 tickL 差值，记为 `M`
4. `WHEEL_RADIUS_M = (2.0 * 1600.0 / M) / (2π)`

或者更简单：**直接量轮子直径**，除以 2。误差 1 mm 对应约 1.6% 的速度误差，看你要求。

### 4.3 标定轮距

轮距误差主要影响转弯。标定方法：

1. 地面标记一个起点，车头朝一个方向
2. 发 `V 0 0.5`（原地左转，角速度 0.5 rad/s）
3. 让它转，同时用秒表计时
4. 转完一整圈（360°=2π rad）应该是 `2π/0.5 = 12.57` 秒
5. 如果实际用时更长 → 轮距设小了；更短 → 设大了
6. `WHEEL_SEPARATION_M_new = WHEEL_SEPARATION_M_old * (实际时间 / 12.57)`

## 5. PID 整定 —— 按步骤来，别跳

工程里的默认值 `Kp=1800, Ki=20000, Kd=0` 是**仿真扫出来的**（`tests/host/pid_sweep.c` 可复现），实车一定要重新整定。

### 5.1 准备

1. 轮子悬空
2. 串口终端里准备好发 `P` 指令
3. 准备观察遥测帧里的 vL 字段

### 5.2 整定 Kp

```
P 0 0 0        ← 先把积分微分清零
V 0.3 0
```

然后逐步加 Kp：

```
P 400 0 0
P 800 0 0
P 1200 0 0
P 1800 0 0
P 2500 0 0
```

每次改完发一次 `V 0.3 0` 重新触发。观察 vL：

- Kp 太小 → 电机转得慢，稳态速度远低于 0.3
- Kp 合适 → 速度能接近 0.3，但会有稳态误差（因为没积分）
- Kp 太大 → 电机"呜呜"响、速度来回振荡

**找到开始振荡的那个 Kp，记作 `Kp_osc`。然后 `Kp = 0.5 × Kp_osc`。**

### 5.3 整定 Ki

保持上一步的 Kp，加 Ki：

```
P 1800 5000 0
P 1800 10000 0
P 1800 20000 0
P 1800 40000 0
```

观察：vL 应该在 1~2 秒内逼近 0.3，且**没有明显超调**。

- Ki 太小 → 稳态误差消不掉，vL 永远差一截
- Ki 太大 → 速度冲过头再掉回来，或者低频"呼吸"

**找到能在 2 秒内消掉稳态误差、且超调 < 10% 的 Ki。**

### 5.4 Kd 一般不用加

编码器速度信号本身噪声就大，Kd 会把噪声放大成 PWM 抖动。除非你的车明显超调且 Ki 已经调小，否则 Kd 保持 0。

> 原文里"先 P 到振荡再减半、然后加 I 消稳态误差、最后少量 D"的思路是对的，跟这里的步骤一致。

### 5.5 验证

```
V 0.3 0
```

3 秒后 vL 应该稳定在 0.300 ± 0.01。然后试试不同速度：

```
V 0.1 0
V 0.5 0
V -0.3 0
```

都能收住才算整定完成。

### 5.6 保存参数

调好后把最终值写回 `board.h` 的 `PID_KP_DEFAULT` 等宏，重新编译烧录。否则断电就丢了。

## 6. 上位机指令速查

| 指令 | 作用 | 示例 |
|---|---|---|
| `V <v> <w>` | 设置线速度(m/s)和角速度(rad/s) | `V 0.3 0.5` |
| `S` | 立即停车 | `S` |
| `Z` | 编码器与里程计清零 | `Z` |
| `P <kp> <ki> <kd>` | 在线修改速度环参数 | `P 1800 20000 0` |
| `R` | 恢复默认参数 | `R` |
| `?` | 查询当前参数 | `?` |

**遥测帧格式**（50 Hz 自动上报）：

```
T,<ms>,<vL>,<vR>,<tgtL>,<tgtR>,<tickL>,<tickR>,<dutyL>,<dutyR>,<lost>
```

| 字段 | 含义 | 单位 |
|---|---|---|
| ms | 系统运行毫秒数 | ms |
| vL / vR | 左/右轮实际线速度 | m/s |
| tgtL / tgtR | 左/右轮斜坡后的目标速度 | m/s |
| tickL / tickR | 左/右轮累计脉冲（可负） | count |
| dutyL / dutyR | 左/右轮当前占空比 | 0~3599 |
| lost | 链路是否超时（1=已自动停车） | 0/1 |

> **断链保护**：500 ms 没收到 `V` 指令，固件会自动停车并把 lost 置 1、LED 常亮。调试时如果发现车"自己停了"，先看 lost 字段。

## 7. 常见问题

### 串口全乱码

晶振问题。蓝丸的 8 MHz 晶振虚焊是常见故障。也可以临时改成内部 RC 时钟（改 `system_stm32f10x.c`），但 RC 精度差，串口会有偏差。

### 一给占空比板子就复位

电源布线问题，回到 2.1 节。要点：电机电源和逻辑电源分开走线、星形共地、电机两端加 0.1 µF 陶瓷电容。

### 轮子转但编码器数为 0

- 编码器没供电
- A/B 相接错（应该接 PA0/PA1 和 PA6/PA7）
- 编码器是开漏输出但没加上拉

### 轮子转但速度读数抖动大

- 检查编码器线是否和电机线绞在一起（串扰）
- 加大 `encoder.c` 里的输入滤波（已经是 0x0F 最大值了）
- 编码器电源加 0.1 µF 去耦

### 车直线跑偏

两轮 PID 各自独立工作，但如果两个电机的摩擦/效率差异大，同一目标速度下实际转速会有差。解决方案：
1. 机械上先保证两边阻力一致
2. 或者加上陀螺仪做航向闭环（下一阶段）

### "小车一顿一顿"

这正是原文提到的问题。本工程已经从设计上规避了：
- SysTick 优先级 1 > USART1 优先级 2
- 控制中断里不做字符串操作

如果你的车还有这个现象，检查是不是在中断里加了 `printf` 或长耗时操作。
